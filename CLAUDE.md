# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A KOReader plugin (`dufs.koplugin`) that launches a bundled [dufs](https://github.com/sigoden/dufs) binary as a web file server (upload/download/delete/mkdir/search, plus WebDAV at the same address) on an e-reader. It is a replacement for filebrowser.koplugin. Server lifecycle logic is in `main.lua`; the rest is packaging: `_meta.lua` (plugin metadata), `bin/` (prebuilt Linux musl binaries), `assets/` (optional custom web UI, including its own modal/editor layer in `index.js`), and `dufs/` (the GitHub release updater).

## Build, run, test

There is no local build step, package manager, or automated test suite; releases are packaged by the tag-triggered GitHub workflow. Verification is manual on a KOReader device or emulator.

- **Deploy**: copy the `dufs.koplugin` directory into KOReader's `plugins/` directory and restart KOReader. The menu entry is Network → Dufs file server: a status line, Start/Stop server, Addresses & QR codes, Settings, Keep server running when sleeping, Stop when idle, and Check for updates.
- **Debug a failed start**: `stop()`/`start()` log to `/tmp/dufs_koreader.log` (its tail is shown in the failure dialog), and the PID lives in `/tmp/dufs_koreader.pid`. On a device shell you can run the server by hand, e.g. `bin/dufs-aarch64 -p 5020 -b 0.0.0.0 -A /mnt/onboard`.
- **Lua syntax check** (if LuaJIT/Lua 5.1 is on the host): `luajit -bl main.lua /dev/null` or `luac -p main.lua`.
- The bundled binaries are Linux ELF (musl) and cannot run on a Windows/macOS dev host; on-device behavior must be validated on the target platform.
- **Updating the dufs binary**: download the musl builds from dufs releases and rename them as `uname -m` maps in `Dufs:getArch()`:
  - `arm7-unknown-linux-musleabihf` → `bin/dufs-armv7`
  - `aarch64-unknown-linux-musl` → `bin/dufs-aarch64`
  - `x86_64-unknown-linux-musl` → `bin/dufs-x86_64`

## How the plugin works

`main.lua` extends `WidgetContainer` (name `dufs`, `is_doc_only = false`) and registers itself into the Network menu via `addToMainMenu`.

**Process management** — there is no daemon/supervisor library:
- `start()` writes `/tmp/dufs_koreader_start.sh` that records its own PID to `/tmp/dufs_koreader.pid` and `exec`s dufs, launches it detached with `sh ... > /tmp/dufs_koreader.log 2>&1 &`, then deletes the script 1.5s later because it contains the password. Liveness is `kill -0 <pid>` plus `/proc/<pid>/comm` identifying a dufs process, so a stale PID reused after a KOReader restart is rejected and the PID file removed; `stop()` sends `kill <pid>`. `isRunningCached()` performs the same PID/comm check without spawning a shell for UI that redraws often (the QuickMenu button).
- **Binary discovery** (`findBinary`): `uname -m` selects `bin/dufs-aarch64`, `bin/dufs-armv7`, or `bin/dufs-x86_64`; fallbacks are `bin/dufs`, then `dufs` on PATH. The chosen file is `chmod +x`'d at discovery time.
- **Server invocation**: `dufs -p <port> -b 0.0.0.0 [--assets <plugin>/assets] --hidden .dufs* (--auth user:pass@/:rw --allow-upload --allow-delete --allow-search --allow-archive | -A) <root>`.
  - `--assets` is passed only when `assets/index.html` exists, so deleting the assets directory falls back to the binary's embedded UI.
  - Auth is enabled only when username *and* password are non-empty; otherwise `-A` grants anonymous full access.
  - `:rw` in the auth rule is bounded by dufs's global operation flags. Without `--allow-upload`/`--allow-delete`/`--allow-search`/`--allow-archive`, an authenticated account is read-only (no uploads, edits, deletes, search or folder ZIPs).
  - Root precedence: `dufs_root` setting → `home_dir` setting → `Device.home_dir` → current directory. `dufs_home` is the UI start folder and breadcrumb home shortcut; it must be inside the root and defaults to the root itself. Address/QR URLs are suffixed with the relative home path. Home is navigation only; the server still serves the whole root.
- **Settings** (`dufs_port`, `dufs_username`, `dufs_password`, `dufs_root`, `dufs_home`, `dufs_keep_on_suspend`, `dufs_idle_timeout`) are persisted in KOReader's `G_reader_settings`; saving the MultiInputDialog validates the port range, requires username and password together (or both empty), checks that root/home exist and that home is inside root, shows a `Settings saved.` message, then restarts the server if it was running.
- **Idle watchdog**: `Stop when idle` offers Off/5/15/30 min/1/2 h. `startIdleWatchdog` checks every minute; it stops the server after `dufs_idle_timeout` minutes without requests (mtime of `/tmp/dufs_koreader.log`, which dufs updates per request) unless `/proc/net/tcp` shows an established connection on the port (long transfers). The timer is cancelled by `stop()` and restarted after start/init.
- **Dispatcher actions** (`dufs_start`, `dufs_stop`, `dufs_toggle`) map to `DufsStart`/`DufsStop`/`DufsToggle` and are registered from `init`; start goes through `NetworkMgr:runWhenOnline`, stop is immediate.
- **Lifecycle hooks**: on suspend, remember whether the server was running and stop it unless `dufs_keep_on_suspend` is enabled; on resume, restart it silently if it was running. Network disconnects do not stop it. On exit, clear the restore flag and stop. On Kindle, start/stop also insert/remove an iptables INPUT rule for the port.
- Startup runs inside `NetworkMgr:runWhenOnline`; the address dialog lists every non-loopback IPv4 address (LAN, Tailscale, USB, etc.) found via `ip addr show`/`ifconfig -a`/`hostname -I`, deduplicated. Tapping an address opens a `QRMessage`, and the `Addresses & QR codes` menu item reopens the same dialog while the server is running. Address rows show only `ip:port` (Tailscale addresses are tagged); tapping opens the QR for the full folder URL, and the dialog notes that both devices must share the LAN or Tailscale. QR support is loaded with `pcall`, so builds without qrencode fall back to a plain InfoMessage. `getLocalIp()` uses `NetworkMgr:getLocalIpAddress()` when the KOReader version has it, else a UDP-connect trick that picks the outgoing interface without sending packets, and remains the fallback when those commands are unavailable.

## Release and updates

- `_meta.lua`'s `version` is authoritative. Pushing a tag `vX.Y.Z` runs `.github/workflows/release.yml`; it refuses to publish unless the tag, `_meta.lua`, `manifest.json` and the web UI's `APP_VERSION` all carry the same version. A hyphen in the tag marks a prerelease, which `/releases/latest` skips.
- The workflow stages the plugin as `dufs.koplugin/`, builds `dufs.koplugin.zip`, and attaches that exact asset to the GitHub release. `dufs/updater.lua` has matching `GITHUB_OWNER`, `GITHUB_REPO`, `ASSET_NAME` and `ARCHIVE_ROOT` constants; keep them in sync with the workflow. The zip includes `bin/`, `assets/`, `licenses/`, `LICENSE`, `main.lua`, `_meta.lua` and `dufs/`.
- `manifest.json` is the Zeno catalog entry and uses the same release asset URL. Its package version must stay in sync with `_meta.lua`.
- The updater is exposed as **Check for updates** in the plugin menu and also runs a silent weekly check from `init` (settings cache `dufs_update_cache.json`). It downloads into `<data>/ota/dufs`, verifies required files and the staged `_meta.lua` version, then swaps the plugin directory with a rollback backup. Symlinked development installs are refused; never remove that guard.

## Custom web UI (`assets/`)

- The UI is a bespoke client, not a patched copy of the stock dufs files: `index.html` (structure), `index.css` (design system), `index.js` (behavior), `covers.js` (lazy EPUB/CBZ/PDF covers read with HTTP Range requests and PDF.js), plus `favicon.svg`, a multi-size `favicon.ico` fallback and `icon.png` for the Zeno manifest, all in the KOReader accent `#00a89c`. Regenerate the ICO from the SVG with ImageMagick: `magick -background none -density 512 assets/favicon.svg -define icon:auto-resize=64,48,32,16 assets/favicon.ico`. Do not merge it with stock `index.js` files from dufs releases; only re-check the endpoints below when the binary changes.
- Visual language is shadcn/ui-inspired (neutral zinc tokens on `:root`, 8–14px radii, quiet borders, light/dark via `prefers-color-scheme`). Folder icons use a blue tinted tile and a lightly filled glyph, while files stay on the neutral muted tile, so list/grid rows remain distinguishable without relying on icon shape alone. The footer shows `APP_VERSION`, the running dufs version parsed from the `dufs-assets-prefix` meta tag, and GitHub/Ko-fi links. Behaviors are File Browser-inspired: list/grid toggle (persisted in `localStorage` under `dufs-view`), client-side sort, right-click / long-press / kebab context menus, multi-select with a floating action bar, and an image lightbox. The move dialog is Nextcloud-inspired (breadcrumbs, navigable folder list, destination summary, “Move here”).
- **All dialogs are native `<dialog>` elements opened with `showModal()`.** The browser supplies the top layer, inert background, Esc (`cancel`), `::backdrop` and focus handling; there is no JS focus-trap code. The `Dialog` class in `index.js` builds the markup, handles animated close (`.is-closing` then `dialog.close()` after `ANIM_MS`), keeps `topLayerCount` for the body scroll lock, and supports `beforeClose` vetoes (e.g. unsaved editor changes). Confirm/prompt helpers promise-wrap it. Nested dialogs (replace confirmation, discard changes) stack natively.
- Entry points in `index.js`: `boot()` reads the base64 `#index-data` template into `DATA`; `ready()` dispatches to `renderListing()` or `setupEditorPage()`; `refreshListing()` re-fetches `?json` and re-renders in place, falling back to `location.reload()`. The standalone `?edit` / `?view` pages reuse the same topbar, dialogs and editor code.
- Feature map: listing/selection/sort (`renderListing`, `updateSelectionUI`, `changeSort`; list file names use measured middle truncation via `fitTableNames`; `formatInfoFor` classifies each extension/basename exactly once in `FORMAT_INFO`/`BASENAME_FORMATS` with a category, Lucide icon and preview kind for books, comics, images, audio, video, archives, code, text, configs, scripts, fonts, databases, keys, packages, discs, subtitles and binaries), breadcrumb (`createBreadcrumb`: home-relative path under `homePath`, home shortcut, root fallback when outside home, measured overflow collapse, hidden-segment dialog, star favorite toggle, reused by the move picker), favorites stored in UI settings and listed in the More menu (`favoritePaths`, `toggleFavoritePath`), row menus and actions (`openItemMenu`, `renameItem`, `moveItem`, `deleteItems`), non-previewable files show a “Preview unavailable” dialog on double-click with Open in new tab when supported and Download (downloads are explicit, via the menu or selection bar; "Open in new tab" is limited to browser-viewable formats such as PDF/audio/video, while EPUB/ZIP only get Download), row clicks select (Ctrl/Cmd toggles, Shift extends the range), clicking outside the rows clears the selection, double-clicking anywhere in the row opens it, and the eye button previews images and EPUB/CBZ/PDF covers, move picker (`openMovePicker`), editor/viewer/lightbox (`openDetailPane`/`renderDetailPane` show text previews, text editing, PDF iframes and browser-playable audio/video in a sticky right pane at ≥1000px; below that width the same actions navigate to the standalone `?view`/`?edit` pages; each split pane has an Open full page action that routes to `?view`/`?edit` and asks before discarding dirty edits; `openLightbox` remains for images), uploads (`Uploader`, drag/drop overlay, batch overwrite confirmation before starting a multi-file upload, aggregate progress bar, pinned active row, collapsed queue summary, completed rows auto-removed, failed rows kept for retry via `PATCH` + `X-Update-Range` or dismissal), toasts, auth and token downloads (`checkAuth`, `downloadUrl`, `setupDownloadWithToken`; sign-in/out items live in the More menu), lazy EPUB/CBZ/PDF covers (`EpubCovers` in `covers.js`; ZIP/OPF parsing over Range, with CBZ using the first naturally sorted image, preferably `cover.*`; PDFs render page 1 with PDF.js and cache the JPEG thumbnail; PDF.js and its standard-font/CMap assets live in `assets/pdfjs/`, loaded on demand from `PDFJS_VERSION`; grid thumbnails and eye actions in both views, with a mouse-hover preview in the list, via `previewSource`/`schedulePreview`; clicking the eye opens the image lightbox or a cover lightbox, which starts with the cached thumbnail and upgrades to the full-resolution image via `EpubCovers.loadFull`; extracted JPEG thumbnails are cached under the configured cache path and fetched before Range parsing; CBR is not supported because it needs a RAR decoder), the settings dialog (`openSettingsDialog`, `loadUiSettings`, `saveUiSettings`), hidden/`.sdr` filtering (`visiblePaths`, `isHiddenName`), and optional sidecar cleanup during delete (`sidecarFor`, `sidecarsFor`). EPUB/CBZ/PDF covers are capped at 8 MB per entry for ZIP-based formats, use at most two concurrent extractions, and fall back to the normal file icon on malformed/encrypted/ZIP64 archives. The split editor keeps `detailState.dirty` in the global beforeunload guard and the standalone `?view` PDF iframe is intentionally unsandboxed so the browser PDF viewer can load; browser-playable audio/video uses native `<audio>`/`<video>`, while other containers are Download-only.
- Web UI settings are stored in KOReader's `settings/dufs-ui/settings.json` and the cover thumbnail cache in `cache/dufs/` when KOReader's data directory is inside the served root (the Kindle default root `/mnt/us` contains `/mnt/us/koreader`, as does the usual Kobo layout). All technical entries live in one hidden `.dufs/` directory at the root; `setupUiStorage()` writes `.dufs/paths.json` with the relative settings/cache paths and `home`, and the UI reads it before rendering. If the served root does not contain the data directory, it creates `.dufs/settings`/`.dufs/covers` symlinks to `<data>/settings/dufs-ui` and `<data>/cache/dufs` and starts dufs with `--allow-symlink`; when symlinks are unavailable (FAT), it falls back to real `.dufs/settings` and `.dufs/covers` directories. Note that `--allow-symlink` applies to the whole root, so any other symlink inside it becomes reachable too. Settings JSON currently holds `{"covers": true|false, "showHidden": true|false, "favorites": ["/path", ...]}`. `.dufs*` is passed to `--hidden`; direct GET/PUT still work. There is deliberately no compatibility with the old `.dufs-ui*` layout. Saving requires upload permission and a writable root. Server-side filtering is avoided: `showHidden` filters paths in the client so `.sdr` folders can be revealed again. When deleting a file with a sibling KOReader sidecar, the confirmation offers a separate checkbox to delete that directory too (unchecked by default); sidecars of failed deletions are kept. KOReader names the sidecar after the file without its last suffix (`Book.epub` → `Book.sdr`), so reuse its `stem + ".sdr"` convention. `assets/index.html` asset URLs carry a `?v=<APP_VERSION>` cache-buster; the release workflow checks it against the tag.
- Delete confirmation tiers (`confirmDelete` + `confirmDialog({ requirement })`): a single file only needs the red Delete button; a single folder additionally requires typing its exact name (with the listing's item count shown); a multi-selection requires typing the item count. The confirm button stays disabled until the input matches exactly, Enter only works once enabled, Esc cancels, and focus starts in the input. Folder names in the dialog are copy-to-clipboard links (`copyableValue`), with an `execCommand` fallback because the plugin is usually served over plain HTTP on a LAN. The server root is never deletable (`isServerRootItem` guards the row menu, selection bar and delete handler).
- Dufs integration relied on: injected `DATA` (`href`, `uri_prefix`, `paths`, `path_type`, `allow_*`, `dir_exists`, `editable`, `user`, `auth`), `?json` (accepts `q`/`sort`/`order`), `?edit` for the editability probe, `HEAD` for move conflicts, `MOVE` with the `Destination` header, `PUT`/`MKCOL`/`DELETE`, `?zip` (folder archives), `?view`, `CHECKAUTH`/`LOGOUT`, and `?tokengen`/`?token` for authenticated downloads. `index.html` must keep the `__ASSETS_PREFIX__` and `__INDEX_DATA__` placeholders that dufs substitutes.
- UI translations live in `assets/i18n.js` (English source strings are keys; dictionaries for pl/de/es/fr; plural forms use `_one`/`_few`/`_many`/`_other`). Language selection is `?lang=xx` (remembered in `localStorage`), `?lang=auto`, otherwise `navigator.languages`. Static markup uses `data-i18n`, `data-i18n-title`, `data-i18n-aria-label` and `data-i18n-placeholder`; JS uses `t()` / `tn()`. Dufs v0.47.0 serves arbitrary files from `--assets` (verified: `/__dufs_v0.47.0__/i18n.js` returns 200), so the dictionaries load as a separate script — do not inline them. When adding UI text, update the HTML/JS and every dictionary.
- Local UI testing: run a dufs build against the assets, e.g. `dufs --assets assets -A <test-folder>` (Windows builds exist). Use a real browser — non-browser clients get dufs's plain no-JS listing instead of the custom UI. `index.html` is read at dufs startup, so restart dufs after editing it; `index.js`/`index.css` are served from disk, so hard-refresh (Shift+F5) after editing them. Functionality worth re-checking after a dufs upgrade: login/token downloads, `?json` listing/sort/search, `?edit` flag, `MOVE`, folder `?zip`, upload retries, `?view`/`?edit` pages, `--path-prefix` deployments, and EPUB cover Range requests in the grid view.

## Constraints and gotchas

- Runs under KOReader's LuaJIT (Lua 5.1) with KOReader modules (`ui/widget/*`, `ffi/util`, `libs/libkoreader-lfs`, `socket` from LuaSocket). Code cannot be exercised with plain desktop Lua.
- Shelling out is POSIX-only (`os.execute`, `sh`, `kill`, `iptables`, `uname`). `sh_ok()` normalizes Lua 5.1's inconsistent `os.execute` return values.
- The password is passed on the dufs command line and briefly written to `/tmp/dufs_koreader_start.sh`; preserve the post-launch script deletion when editing `start()`.
- Without credentials the server is unauthenticated and reachable by anyone on the LAN.
- Keep the plugin directory named `dufs.koplugin`: `getPluginDir()` relies on `self.path` (set by KOReader from the installed directory), falling back to the `main.lua` source path.
